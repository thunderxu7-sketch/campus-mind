# 表达与支持助手：营销定位与执行手册

版本：1.0 · 日期：2026-09-14 · 状态：**可执行策划稿，新增功能尚未开发**。

适用对象：产品负责人、销售、市场、设计、专业负责人。配套：[开发执行规格](15-expression-support-implementation.md)。

## 1. 一页决策

| 项目 | 本版决定 |
|---|---|
| 对外名称 | **校园心晴 · 表达与支持助手** |
| 核心定位 | 学生自愿表达、选择分享、发起支持请求，学校专业人员接单、沟通和随访 |
| 视觉功能名称 | **可选面部动作互动**：设备内驱动虚拟形象，不解释内在情绪 |
| 核心卖点 | 从“完成一次测评”延伸到“学生主动表达与持续支持” |
| 明确不卖 | 微表情心理识别、摄像头测抑郁、情绪监控、专注度考核、测谎、自动心理风险排名 |
| 第一批验证对象 | 有心理教师、已有测评/预约流程、愿意讨论隐私边界的初中学校；这是客户假设，不是已签客户 |
| 首次展示方式 | 合成记录 + 预设虚拟形象动画；无需摄像头，不接真实学生账号 |
| 本轮交付边界 | 两份方案文档，不代表功能已实现、产品已合规或试点获准 |

**原则：视觉互动吸引体验，支持闭环形成业务价值；不能把前者包装成后者的科学依据。**

## 2. 为什么不营销“微表情读心”

### 2.1 面部运动不等于内在情绪

面部运动与情绪之间存在情境、个体和文化差异，不能将某个面部动作视为特定情绪的可靠诊断标志。模型的动作分类表现也不等于心理筛查效能。[研究综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC6640856/)

经典微表情数据集 CASME II 在受控环境使用 200 fps 摄像机，参与者平均约 22 岁。原文讨论了情绪标签、场景及年龄局限；它不是普通校园摄像头识别儿童心理问题的效果证据，也不是当前算法性能上限。[原始论文](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0086041)

### 2.2 可信任比“黑科技”更重要——待客户验证的商业判断

本项目假设：学校愿意为可接续、可审计、可说明的数据流程付费，家长与学生更愿意使用不强制拍摄、不贴标签的工具。不得把这段假设当作市场调研结论，按第 8 节验证。

**不能通过改名为“辅助分析”“仅供参考”，继续输出面部情绪、心理分值或风险判断。**

## 3. 客户、需求与价值主张

| 对象 | 要验证的工作痛点 | 产品价值主张 | 应展示的证据 | 不应索取的资料 |
|---|---|---|---|---|
| 校方决策者 | 求助处理是否分散、是否遗漏、值班是否明确 | 状态可追踪、责任人明确、异常可接续 | 合成请求的接单和提醒失败演示 | 学生名单、心理报告、真实个案截图 |
| 心理教师 | 会前资料整理是否重复，是否难管理后续联系 | 学生授权分享、个人收件箱、预约与跟进 | 授权范围、失效处理、状态时间线 | 用于“训练算法”的咨询记录 |
| 隐私/信息化负责人 | 谁能访问、能否撤回、第三方拿走了什么 | 对象级授权、可审计、最小数据流 | 数据流图、撤回测试、网络检查结果 | 生产密钥、系统管理员密码 |
| 学生与家长 | 是否被强迫拍摄、是否被老师误解、能否控制分享 | 无摄像头也可使用；分享对象和期限可见 | 适龄说明、拒绝和关闭路径 | 面部视频、家庭敏感经历、身份材料 |

明确拒绝的需求：接入教室监控、批量读表情、按情绪安排座位/处分/评优、按参与率考核学生、通过家长同意绕开学生拒绝。

## 4. 产品包装与商业边界

以下是报价结构建议，**不是已经开售的 SKU、价格或服务承诺**。

| 包装 | 包含 | 适合的采购问题 | 不包含 |
|---|---|---|---|
| 测评与管理基础包 | 本项目经过验收的组织、授权量表、任务、报告等能力 | 怎样规范组织测评与专业复核 | 未授权量表、医疗诊断 |
| 表达与支持扩展包 | 自愿记录、选择分享、普通支持请求、接单、跟进、已有预约衔接 | 怎样承接学生主动表达 | 实时救助保证、自动情绪判定 |
| 可选互动组件 | 经独立验收的端侧虚拟形象互动 | 怎样增加自愿体验的可操作性 | 情绪识别、录制、考勤、视觉数据分析 |
| 实施与运维服务 | 配置、培训、数据边界核验、恢复演练、约定的支持服务 | 谁负责持续运行 | 未签约的 24 小时人工心理服务 |

报价顺序：明确部署与覆盖范围 → 估算基础设施、通知、实施培训及运维工作量 → 核验第三方商业授权 → 内部审批报价。按学校/服务范围计费，不按“识别出多少问题学生”计费；不得虚构硬件采购必要性。

成本清单必须包括：基础平台生产化缺口、专业/隐私审查、支持人员培训、通知通道与备份、可选视觉组件设备兼容测试。不能只报“接一个 SDK”的成本。

## 5. 可直接使用的文案

### 5.1 目前可发布：明确为规划

**主标题**

> 让孩子愿意表达，让每一次求助都有回应。

这是产品愿景，不是“100% 接单”或任何时限内响应的保证；页面必须同时展示当前版本状态和实际服务边界。

**副标题**

> 校园心晴正在规划「表达与支持助手」：通过自愿记录、选择分享和专业人员接续，让校园心理支持不止于一次测评。

**功能卡片**

1. **自愿表达**：规划支持文字与主题选择，不强制回答、不要求打开摄像头。
2. **选择分享**：规划由学生确认分享给谁、分享哪条记录、何时失效。
3. **专业接续**：规划为普通支持请求提供接单、联系、跟进和状态查询。
4. **可选视觉互动**：规划在设备内驱动虚拟形象，不生成情绪或心理标签。

**CTA**：`查看合成演示`、`阅读隐私与功能边界`、`联系团队讨论试点条件`。

没有真实可用的收件渠道前，第三个 CTA 不上线；不能用无响应按钮或默认收集学生资料的表单代替。当前无演示功能时，第一个 CTA 改为 `阅读功能规划`，链接到配套规格。

### 5.2 完成相应验收后才可发布

> 学生可以主动记录和选择分享，心理教师在授权范围内接收支持请求并跟进。可选的面部动作互动在设备内运行，不上传面部画面、不生成心理标签。

适用限制必须紧邻展示：

> 这不是心理诊断或实时救助服务。摄像头可关闭，不影响表达、预约和帮助资源的使用。具体服务时段和响应安排以学校公布的信息为准。

“分享可撤回”必须同时解释：撤回阻止后续通过本功能访问，无法让已经看到的信息消失；已经依法形成的独立专业记录按相应规则处理，不能承诺所有资料立即消失。

### 5.3 销售开场白（约 30 秒）

> 我们不靠摄像头判断孩子有没有心理问题。这个模块希望解决的是：学生愿意表达之后，信息如何在本人知情的范围内到达合适的老师，以及后续有没有人接续。视觉互动是可选体验，真正的核心是自主表达、授权分享和支持流程。目前先提供合成演示，真实学生使用需要学校与专业、隐私负责人共同确认。

### 5.4 禁止话术与替代

| 禁止或不可证实的话术 | 可使用的准确表述 |
|---|---|
| 30 秒看穿真实情绪、识别伪装 | 学生主动表达，系统记录本人提交的内容 |
| 摄像头发现隐藏抑郁、预测危机 | 使用经审定的测评与人工支持流程，不从面部生成心理风险 |
| 全校无感实时心理监控 | 非持续、非强制的个人互动；不接入课堂监控 |
| 微表情识别准确率 95% | 本功能不输出情绪准确率；展示已验证的技术和流程指标 |
| 绝对匿名、绝对安全、永不泄漏 | 明确采集内容、访问范围、保存规则和已验证的保护措施 |
| 100% 不收集任何个人信息 | 视觉数据不上传；主动提交的表达记录按告知用途受控处理 |
| 已通过国家认证、完全符合所有法规 | 只陈述有可核验文件、明确范围和有效期的审批/认证事实 |
| 免费试用请上传学生名单 | 使用合成账号演示，真实数据另走准入流程 |

## 7. 三分钟演示脚本与物料

默认演示使用合成身份和内容；不能临时请学生提供真实困扰或现场摄像来“证明准确”。

| 时间 | 操作 | 必说内容 | 成功标准 |
|---|---|---|---|
| 0:00–0:30 | 首页显示状态与边界 | 当前是合成演示；不做微表情心理识别 | 观众看得到“合成”与“非诊断” |
| 0:30–1:00 | 跳过视觉互动；选择“想聊聊学习安排” | 不开摄像头不影响使用 | 不出现授权弹窗，能继续 |
| 1:00–1:40 | 保存，再选择合成咨询师和分享期限，单独发起联系请求 | 保存、分享、请求联系是三个不同决定 | 页面逐步显示各动作结果 |
| 1:40–2:20 | 教师端接单；学生看到状态 | “已提交”不等于“老师已接单” | 状态变化有依据，无虚假回应 |
| 2:20–2:45 | 撤回分享，刷新教师详情 | 后续访问被阻止，已看到的信息无法回收 | 内容不可再次读取，流程状态仍清晰 |
| 2:45–3:00 | 展示预设虚拟形象动画与帮助入口 | 动画不是心理分析；互动可以随时跳过 | 不出现情绪分值或风险标签 |

若尚未完成交互原型，用标有“设计稿”的逐屏讲解代替，不假装后台已经处理请求。

待制作物料：

- [ ] 一页产品介绍：定位、三个业务功能、可选互动、边界、当前状态。
- [ ] 三分钟演示：上述步骤、合成数据水印、无真实姓名/校徽/影像。
- [ ] 采购问答：权限、留存、撤回、部署、值班、价格构成。
- [ ] 试点条件清单：具名负责人、服务时段、备援、隐私与专业批准、停止条件。
- [ ] 主张证据表：复用第 6 节，技术负责人填写真实验证结果。

## 8. 获客与验证执行顺序

以下数量是本项目的调研计划，不是市场事实；对外联络、付费投放和发布须另获明确执行授权。

| 顺序 | 负责人 | 动作与产物 | 进入下一步条件 |
|---|---|---|---|
| MK-01 | 产品 + 专业负责人 | 审阅本手册和原型，确定适龄文案；列出不做事项 | 无情绪推断或强制拍摄暗示 |
| MK-02 | 产品/销售 | 访谈 3 所候选学校，每校尽量包含心理教师和信息化/管理人员；记录流程而非学生个案 | 至少识别一项可通过流程解决的痛点；否则修改定位 |
| MK-03 | 设计 + 产品 | 制作合成演示，分别演示有无视觉互动的流程 | 测试者能说清“系统不推断心理状态”及分享边界 |
| MK-04 | 销售 + 技术 | 向符合条件的学校提供范围清单、缺口说明和成本构成 | 不以摄像头诊断为成交条件，不承诺未交付功能 |
| MK-05 | 校方 + 专业/隐私负责人 | 制定受控试点协议、数据规则与值班安排 | 原项目及新模块生产门槛全部通过 |
| MK-06 | 产品 + 市场 | 评估结果，批准范围内制作匿名化案例或继续优化 | 经核验可公开、无法识别学生，不把可用性成果写成临床效果 |

访谈题：目前求助从哪里进入？谁负责接单？未接单如何发现？哪些信息不应让管理者看到？学生拒绝摄像头是否仍能接受方案？采购愿意为哪项流程改善付费？不询问特定学生的病史或咨询内容。

## 9. 效果指标与口径

新模块第一版不接入广告追踪、第三方会话回放、个体画像或摄像头使用埋点。

| 指标 | 定义 | 使用限制 |
|---|---|---|
| 核心流程完成率 | 合成可用性测试中，独立完成“提交请求并查看状态”的人数 / 尝试人数 | 报告设备、任务和样本量；不代表心理健康改善 |
| 首次接单时长 | `firstAcknowledgedAt - createdAt` 的 p50/p95 | 仅有明确接单记录的普通请求；同时报告未接单数，不能仅挑成功请求 |
| 到期未接单数 | 当前未接单且 `ackDueAt <= 统计时刻` 的普通请求数量 | 逾期指服务流程，不是学生心理高风险 |
| 服务跟进完成情况 | 已进入跟进且按约定到期完成的请求 / 到期应跟进请求 | 明示取消/转出/样本范围；不代表治疗效果 |
| 工作耗时变化 | 同类任务在试点前后由工作人员记录的处理耗时 | 有样本和基线才可对外陈述，避免因果夸大 |

真实数据的汇总只在已批准用途内进行。首版不新建校长心理状态看板；如制作学校级汇总，复用原项目的小样本抑制与查询保护规则，不按学生、班级或面部动作钻取。小样本门槛是保护措施，不是匿名保证。

## 10. 发布与停用规则

- 发布前：产品核对状态 → 技术核对证据 → 专业负责人核对心理表述 → 隐私负责人核对数据承诺 → 市场按批准版本发布。真实准入证据留在批准的私有位置，不进公开仓库。
- 只完成文档时使用“规划/拟支持”；合成参考版完成后使用“合成演示”；真实试点批准后只对批准范围使用“试点”。不得跨级。
- 出现越权读取、误导性心理标签、摄像头关闭失败、通知无法接续或学生被强制参与时：暂停相关功能/宣传，联系具名责任人处理；不等待下一次营销迭代。
- 本轮仅创建文档，不自动改写 Pages 宣传、收集销售线索、联系学校或发布活动。
