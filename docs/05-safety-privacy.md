# 安全、隐私与专业治理

这是研发控制清单，**不是法律意见、临床方案或合规认证**。官方来源见[依据与决策](09-sources-and-decisions.md)。当地实施、医疗边界、授权文件须由具备相应职责的校方、专业与法律/隐私人员确认。

## 1. 不可降低的产品红线

| 原始表述 / 风险 | 本项目规则 |
|---|---|
| 所有管理员公用一个公账号 | 具名独立账号、最小权限、MFA；导入权限不等于心理档案权限 |
| 焦虑/抑郁分值决定危机 | 分数只产生候选线索；结合合法获取的访谈/观察，由专业人员判断 |
| 自动解除预警 / 达到正常 | 自动生成待复核提醒可以；结案由授权专业人员审查，不宣称系统判定恢复正常 |
| 网络成瘾诊断 / 提供治疗 | 改成相关维度筛查、教育支持与转介记录；医疗诊断和治疗不作为学校平台业务 |
| 管理员随意修改报告解释 | 草稿可编辑，专业复核后发布；量表算法与阈值不允许无审查改写 |
| 任意年龄、任意时间反复测评 | 学段适用性、有效同意、校方频次政策、值班能力共同控制 |
| 普查数据直接用于研究 | 服务与研究目的分开；另行伦理/合法性审查和授权，去标识化仍需保护 |

## 2. 知情、监护与权利

以自愿参与为设计基础。告知内容包含用途、字段、所需性、接收范围、保存期、风险处置保密边界、服务时段和权利渠道。不能以参与率 KPI 迫使学生完成心理测评。

不满 14 周岁的流程包含监护人同意和专门处理规则；14–17 岁同样需要敏感资料保护、适龄告知及适用的同意安排。心理健康信息的单独同意与其他合法依据之间如何适用，由法律负责人按具体处理活动记录，不将学校身份视为无限豁免。[个人信息保护法](https://nmca.miit.gov.cn/zwgk/zcwj/flfg/art/2021/art_0bb3c8d9e620423fb4deeb85e1b751c5.html)

- 学生可以拒绝或撤回；普通心理知识/帮助信息仍可使用。
- 撤回需停止相应用途的新处理，取消未执行任务和导出，评估既有记录删除/限制处理；不能假设撤回等于自动删除所有法定保留证据。
- 报告默认不公开与权利申请渠道同时存在；不能用“学生不可见”设置拒绝依法查阅。核验身份、及时受理，若依法限制需书面理由与救济路径。
- 高风险应急处理仅在适用依据与必要范围内进行；权限扩展、联系对象、事后说明及审核留痕，不能以“安全”为由给所有教师开全量档案。

## 3. 量表治理 Gate

每个拟发布量表/方案必须有：

1. 名称、作者/权利人、版本、语言与翻译来源、授权合同或许可证据、数字化/商业使用范围及期限。
2. 适用年龄、学段、地区、答题主体（学生/家长/教师）与施测条件；适用性证据及局限。
3. 官方计分、反向项、缺失处理、因子、常模、阈值来源；专业负责人书面审定。
4. 独立于开发实现计算的测试向量：正常值、边界、反向项、缺失、不适龄、异常作答；逐项差异须解释。
5. 报告解释与学生适龄反馈审核、危机线索处理协议和量表失效/撤销处置方案。

MVP 不预置来源不明的商业量表。开发只用显著标记 `synthetic_only` 的自建演示问卷，**不称为有效心理量表**，生产发布时必须拒绝该标志。低龄群体不得继承中学生/成人常模。版权与专业签字未就绪不阻碍合成数据开发，但阻断真实学生使用。

## 4. 数据最小化与分级

| 分类 | 例子 | 默认控制 |
|---|---|---|
| 公共教育内容 | 已审文章、中心公开介绍 | 内容审查与版权、可公共缓存 |
| 基础个人资料 | 姓名、学校班级、必要监护联系方式 | 按职责查看，加密敏感字段，不默认收身份证/家庭收入 |
| 高敏心理资料 | 原始答案、因子、报告、线索、支持记录 | 最小个案授权、加密、读取/导出审计，不进日志/第三方模型 |
| 安全与合规证据 | 同意记录、访问元数据、审批、删除台账 | 独立权限、完整性保护、按适用保存政策处理 |

自定义调查字段须逐项说明目的、必要性、选填/必填、可见范围和保留期，审核后发布版本。禁止任意表单把家庭创伤、宗教、医疗诊断等变成学校管理的默认必填项。

## 5. 留存与删除（需 M0 签字）

不能凭项目名称随意写“心理档案永久保存”。每类数据设置 owner、目的、触发点、最短必要期限、适用保留依据、删除/匿名化方法及例外审批。

- 导入原文件、导出产物：确认完成后尽快删除；精确 TTL 在运营政策中配置，未配置不得上线。
- 未提交答卷：期限到达或撤回后清理，不把草稿永久并入档案。
- 正式答卷/报告/个案：校方与专业、隐私人员确定期限及离校处理。保留决定不自动开放访问。
- 日志与合规证据：区分访问日志、业务审计和法定评估记录，不统一套用同一期限。
- 删除覆盖主库、对象、检索索引、临时文件、缓存及异步任务。备份无法即时逐条删除的，应限制访问、到期销毁，恢复时重放最小删除台账；台账自身最小化且按批准期限保留。

## 6. 聚合统计与导出

先固定学校/学年/年级等允许维度；性别、年龄等只在必要且样本充分时提供。默认设计阈值 `k = 10` 为工程草案，不是法定值，也不是匿名保证。

同时实施小单元抑制、互补抑制（避免由总数相减复原）、跨筛选查询限制与审计、禁止任意钻取到个体、角色维度白名单。小班级不显示心理风险分布。任意层级可识别某名学生的统计不应作为公开报表。

导出需审批字段、目的、范围、水印、到期；原始答案导出默认关闭。Excel/CSV 防公式注入，附件不生成公开 URL，不能用监护人转发链接验证身份。

## 7. 危机响应是人员流程，不只是算法

- 上线前落实具名值班、备用联系人、接单/复核/升级时限、夜间流程、转介机构和演练；具体时限由校方与专业负责人制定，本文不编造医疗响应承诺。
- 任何时段都提供清楚的人工/紧急帮助说明；预约和未提交问卷不是有人实时监护的保证。
- 通知失败、无人接单、计分失败有明确异常队列与人工接续。故障不能静默吞线索。
- 支持内容由专业人员制定；平台记录事实和工作流，不自动开处方、下诊断或推荐医疗治疗方案。
- 若发现风险提示设计有伤害、线索无法承接、系统误发布诊断性结果，应停止真实测评并人工接管，而非等待下一迭代修复。

## 8. 运营前必须完成

- 确认个人信息处理者/受托者责任，供应商协议与数据流图；完成个人信息保护影响评估及必要的本地法律审查。
- 对适用的网络安全等级保护、备案、未成年人合规审计/报告及当地教育部门规范进行核查，**不预判必定属于某个等保等级或只做一项备案即合规**。
- 建立年度未成年人信息处理合规审计安排；访问审批和记录应可核查。[未成年人网络保护条例](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)
- 生产账号、通知、对象存储和备份均审查；只将合成工程材料放 GitHub，不把私有仓库当成学生数据保险箱。
- 真实数据不发往通用 LLM、境外统计/错误收集平台或开发者个人网盘；若未来需要新用途，先独立治理审批。
