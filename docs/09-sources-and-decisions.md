## 2. 原需求修订台账

| 决策 | 原意 | 采用方案 | 原因 / 类型 |
|---|---|---|---|
| D01 | 11 个子系统但列举不全 | 按 S01–S11 重新归并，补齐账号、参与和量表治理 | 工程分解假设，可调整 |
| D02 | 管理员共用公账号 | 具名账号 + 最小范围 + 操作审计 | 可追责与儿童资料访问保护，R05 |
| D03 | 自动解除危机预警 | 系统提示待复核，专业人员审核结案 | 安全设计：单次分数不足以判定实际状况 |
| D04 | 诊断、自控诊断、网络成瘾诊断、治疗 | 对应维度筛查、支持工作记录、必要时医疗转介 | 业务资质与功能边界，R04 |
| D05 | 所有人随时不限次数测评 | 适龄、知情、频次与人员承接条件满足后开放 | R01/R02；不将云端可达误写成全天救助 |
| D06 | 管理员自改报告与指导 | 可版本化编辑，但由专业负责人审批 | 防止未经审查的解释或规则改动 |
| D07 | 全量档案按部门共享 | 区分名册/完成状态/心理原始资料；个案与用途授权 | 最小化数据访问，R03/R05 |
| D08 | 普查为研究直接提供数据 | 服务与研究用途分开审核；不默认共用授权 | 目的限制与伦理审查，R03 |
| D09 | 重复在线预约 | 合并为排班、预约、取消改期和回执 | 去重，无新增即时治疗范围 |
| D10 | 焦虑抑郁分值找出原因 | 提供测量维度线索和局限，不推断病因或医学结论 | 专业安全边界 |
| D11 | 所有学段同一实现 | 先初中试点，逐学段验证；低龄先教育与人工支持 | 适龄性与负担控制，R01 |

上述为当前规划的建议变更，并不声称校方或采购方已签字确认；CM-001 要完成正式确认。

## 3. 技术与实施假设

- TypeScript + React/Vite + NestJS + PostgreSQL 为建议，不是用户指定；初始化时重新核对依赖支持与安全状况。
- 多租户使用应用权限及 PostgreSQL RLS 双层防护；官方说明表所有者/特权角色可能绕过行级策略，运行身份必须受限。[PostgreSQL 文档](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
- 默认国内数据平面、GitHub 私有工程仓库；不代表已购云服务、已部署、已签数据处理合同。
- `k = 10`、1,000 并发与恢复目标是容量/隐私讨论基线，非政策规定、已测性能或匿名化证明。
- “初中一校 MVP”用于控制产品试点范围，不代表已获得该校授权或学生同意。
- 不提供预算与日历承诺，缺少人数、团队与专业审批证据时只提供依赖和 Gate。
