# 产品需求与范围 · v0.1

状态：规划草案，2026-09-11。输入为用户提供的系统说明；以下拆分是工程方案，不代表现有系统已经具备这些能力。

## 1. 定位、目标与边界

面向中小学的学校心理健康教育与支持工作平台，服务组织普查、个体筛查、心理档案、专业复核、支持转介和管理统计。**不提供精神障碍自动诊断，不替代医疗机构，不作学生品行或升学评判工具。**

产品成功不以“发现多少高风险学生”为目标：重点考察自愿参与体验、有效数据质量、待复核线索及时承接、随访完整性及隐私保护。量表分数只能提示当前测量维度，不能推断心理问题的确定病因。

### 默认假设

- 先在中国大陆一所学校的初中学段试点；多校 SaaS 的隔离能力从数据模型起建立。
- 客户为学校/教育服务机构；责任主体及委托关系在 M0 明确，不假定 SaaS 运营方拥有数据。
- PC / 平板 / 手机 / 触屏终端通过响应式网页使用；“PC 服务端”按学生服务门户与工作人员管理端理解，不是另一套后端。
- 学生无个人手机时可使用学校独立的一次性凭证登录；不能让整个班共用账号。
- 教师负责日常关怀，心理专业人员负责复核和支持，医疗诊疗由合规医疗机构承担。
- 需要人员在测评开放时段承接风险线索；无人值守不能把平台宣称为实时救助服务。

## 2. 十一个子系统与需求映射

原材料声称 11 个子系统，但没有完整列出 11 个名称。下表是补齐权限、知情参与、量表治理后重新归并的 **11 个工程子系统**。

| ID | 子系统 | 原需求对应 | 核心交付 | 范围 |
|---|---|---|---|---|
| S01 | 组织与账号权限 | 管理员、部门与人员授权 | 学校/学年/年级/班级、独立账号、角色、数据范围、MFA | MVP |
| S02 | 人员采集与知情参与 | Excel、自定义人口学调查 | 导入预检、组织映射、监护关系核验、告知及同意/撤回、最小字段 | MVP 基础；自定义调查 M5 |
| S03 | 量表与计分 | 多维量表、因子、图表和解释 | 授权证据、适龄与常模、不可变版本、计分验证、专业审定 | MVP 一个合规方案；扩库 M5 |
| S04 | 普查与任务 | 全校/年级/班级、指定人群与时间 | 名单快照、窗口、参与政策、频次、分发、完成率 | MVP |
| S05 | 筛查与测评端 | PC/移动端接收完成任务 | 知情参与、答题、服务端保存、恢复、提交、反馈 | MVP 任务入口；自选入口 M5 |
| S06 | 档案与报告 | 基本信息、结果、分类归档与输出 | 时间轴、量表版本、报告审核/发布/撤回、水印导出 | MVP |
| S07 | 危机预警 | 分值识别、风险评估、专家审核 | 规则候选线索、人工复核、指派、接单和超时升级 | MVP |
| S08 | 干预与随访 | 干预中心、辅导和解除预警 | 支持计划、接触记录、转介回执、随访、人工审批结案/重开 | MVP 基础；复杂协作 M5 |
| S09 | 统计分析 | 按学校/科室/性别/年龄/量表统计 | 统计字典、基数与缺失值、聚合抑制、趋势、审批导出 | MVP 基础；区域分析 M5 |
| S10 | 咨询预约 | 咨询师介绍、两处重复在线预约 | 资质审核、排班、预约/取消/改期、防冲突和提醒 | M5；MVP 保留人工转介登记 |
| S11 | 心理教育门户 | 公告、文章、文件、音视频、用户 | 专业审核发布、内容适龄分级、资源检索和支持入口 | M5；MVP 含静态说明/帮助 |

“学习方法/习惯、考试焦虑、交际、自控、网络使用、人格”等是 S03 的候选维度，并不意味着每个维度已有合规适用的量表。“自控/网络成瘾诊断”在产品中改称对应维度筛查，不把测试解释写成诊断。

## 3. 首个 MVP 的完整闭环

1. 校方用独立账号建立组织、导入最小名单并完成告知/监护流程。
2. 专业负责人确认一个适龄、有授权且计分经独立验证的测评方案。
3. 管理员发布一次学校任务，冻结受测名单、量表版本、学年频次和可见性政策。
4. 学生自愿进入；未同意/撤回仍可获取非个体化心理知识和人工求助信息。
5. 保存并提交答案；系统展示明确持久化状态，生成可追溯计分结果和待审报告。
6. 风险线索及时进入专人工作队列；无需等待报告审核完成才提醒工作人员。
7. 专业人员复核、确认支持需求、记录支持与医疗转介、安排随访。
8. 结案必须人工申请与授权审核；基础看板呈现完成情况及去标识聚合。

**不作为 MVP**：公开即时聊天、视频问诊、在线治疗、AI 咨询机器人、情绪摄像头、全校风险排行榜、商业化收费结算、跨机构自动交换档案、离线完整答题、区域大数据仓库。

## 4. 功能验收约束

- Excel 导入：支持映射预览、重复/冲突/必填校验、错误行反馈、批次结果；自动发现的组织必须人工确认，不直接成为有效授权边界。
- 任务分发：普查/筛查是用途标签，共用引擎；不得重复创建名单绕过测评频次。期限变化可审计，已开始任务的版本不被静默替换。
- 测评：不做考试式倒计时施压；提交失败、断网、保存冲突、版本过期均有可理解反馈。
- 报告：专业解释先审后发；允许模板个性化，但不能随意改原始计分及专业解释。敏感报告不能通过公开分享链接访问。
- 档案：转班不会自动扩大历史咨询记录权限；转学只允许审批后的最小信息转移，不能直接暴露原校租户资料。
- 预警：包括专业人员手工记录或学生主动求助，不依赖某一个焦虑/抑郁分数；低分不作为“无风险”证明。
- 统计：明确分母、有效样本、未完成与无效答卷；风险线索比例不是疾病患病率，不能作学校好坏排名。
- 预约：两处原始预约需求合并；预约不是即刻获得咨询，更不是紧急救助入口。

## 5. 非功能要求（待容量验证）

| 维度 | 规划目标 / 验证条件 |
|---|---|
| 可用性 | 普查开放前检查数据库、存储、队列、值班和通知；故障可暂停新增任务 |
| 性能 | 暂以 1 万在册、1,000 并发在线、100 次保存/秒为合成压测基线，非已验证容量；M0 确认后调整 |
| 延迟 | 在该基线下保存/提交确认 p95 ≤ 1 秒，异步计分 p95 ≤ 30 秒；风险直达链路单独测量，不以报告排队时间代替 |
| 持久性 | API 显示“已保存”前事务必须提交；重试不丢不重复，故障恢复实际损失按 RPO 演练记录 |
| 恢复 | 暂定 RPO ≤ 15 分钟、RTO ≤ 4 小时；评估能否满足校方，恢复期间启用线下安全流程，不承诺零丢失 |
| 无障碍 | 键盘、可见焦点、字号缩放、色彩不单独表达风险；360px 至桌面宽度；触屏设备结束后清除会话 |
| 运维 | 敏感访问审计、结构化脱敏日志、队列积压与无人承接告警、通知供应商故障演练 |
