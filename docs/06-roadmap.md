# 开发路线图

## 1. 阶段路线：先安全闭环，再广覆盖

以下是依赖顺序，不是合同排期。尚无团队人数、试点学校、量表许可到位日期和采购预算，**不承诺固定周数或报价**。M0 完成后按负责人可用产能估算关键路径；专业/法务审批等待与工程工时分别记录。

| 阶段 | 交付 | 退出 Gate |
|---|---|---|
| M0 · 范围与专业治理 | 明确试点、责任、量表来源、告知与危机方案、容量基线 | 需求差异获确认；真实数据前置条件有具名责任人与证据；未获许可只准合成开发 |
| M1 · 安全基础 | 单仓工程、环境、身份、多租户、数据分级、审计、导入和参与流程 | 两个合成学校的隔离/角色/同意测试通过，日志无心理资料 |
| M2 · 测评与报告 | 量表配置、金标准计分、任务、频次、答题恢复、报告审定与档案 | 合成端到端闭环通过，计分可复现，草稿/提交/历史版本不被覆盖 |
| M3 · 预警与支持闭环 | 线索、人工复核、接单/升级、支持转介随访、人工结案 | 故障演练证明不静默丢线索、不自动结案，人员承接与备用路径到位 |
| M4 · 试点就绪与验收 | 基础统计、权利与删除、导出、压测、恢复、安全评审、校方验收 | 所有 P0 + M4 内所有任务验收；审批/许可/人员到位，才允许受控真实试点 |
| M5 · 完整版扩展 | 预约、内容门户、自定义调查、扩学段/量表、自选筛查、区域能力 | 每项分别评估适龄、隐私、版权和人员容量；不沿用试点结论自动放开 |

**MVP 是 M1–M4 全部核心闭环，不是做完答题界面即可上线。** M2 可以演示合成数据，但不得绕过 M3/M4 在真实学校试用。

## 2. 工程关键路径

`组织/身份隔离 → 最小名单与知情参与 → 已审定量表版本与计分 → 任务/频次 → 可恢复答题/不可变提交 → 风险可靠投递 → 人工处置与随访 → 试点验收`

可同步推进但不代表启动子代理：专业团队准备许可和计分金标准；产品做学生知情参与原型；后端做租户与审计；前端用合成契约开发页面。没有授权量表时不得“先拿真实学生试一下”。

## 3. 首批执行顺序

1. **PM + 校方/专业负责人**：确认初中试点、业务责任和原始需求修订；选定测评方案，拿到授权与适龄依据。
2. **设计 + 前端**：完成管理端和学生端低保真流程，重点验证告知、拒绝、保存失败、复核与安全求助，不先做装饰性大屏。
3. **后端 + 安全**：建立双租户合成样本、对象授权、审计和会话；证明班主任不能看答卷、平台运维不能看个案。
4. **前后端**：最小导入与同意、任务与频次、纯计分引擎、答题恢复、报告审核。
5. **专业 + 全栈 + QA**：预警、接单和超时演练；之后补齐统计、权利处理、恢复与试点验收。

## 4. 人力与责任（不是已分配人员）

| 工作流 | 所需责任角色 | 不可替代的责任 |
|---|---|---|
| 产品与学校落地 | 产品负责人、校方负责人 | 需求口径、参与流程、学校值班与验收 |
| 心理专业 | 专业负责人、独立复核者 | 量表适用性、金标准、报告解释、风险/结案政策 |
| 工程 | 前端、后端/全栈、运维 | 可靠实现、最小权限、发布和恢复 |
| 质量与治理 | QA、安全、隐私/法律 | 独立验收、影响评估、权限测试、事件处置 |

一个人可以覆盖多个工程岗位，但关键专业审批不能靠工程人员自签；缺少校方承接人员会阻断真实试点。

成本评估项：工程工时、量表授权、专业评审/值班、国内数据库与对象存储、备份/KMS、通知用量、安全与合规评估。采购前按试点规模取报价，不先开通付费服务。

## 5. P0 / P1 / P2 语义

- **P0**：安全与首个真实试点必需；不可因赶进度降为“后续完善”。
- **P1**：完整工作流和运营效率；其中被 M4 Gate 点名的项仍是试点必需。
- **P2**：在证据和资源支持下扩展，不影响首个试点闭环。

逐项依赖见[开发清单](07-task-breakdown.md)。每个任务的 owner 是责任岗位，不虚构已接受任务的人员；任务状态以 `planning/backlog.json` 为准：`done` 表示参考实现与自动化证据已完成，`in_progress` 表示仍需生产/治理证据，不表示真实试点已获准。

## 6. Open Questions / 决策登记

| ID | 待确认事项 | 暂用方案 | 最迟决策点 |
|---|---|---|---|
| Q01 | SaaS 多校还是单校私有化？地区与责任主体？ | 单校初中试点、多租户模型、中国大陆数据面 | M0 结束 |
| Q02 | 第一套量表、版权、常模、适龄及施测资格？ | 不指定商品/诊断阈值；合成数据开发 | 量表发布/真实试点前 |
| Q03 | 学校服务时段、紧急联系、复核与结案责任人？ | 不宣称全天在线救助；真实测评需值班配置 | M3 演练前 |
| Q04 | 监护关系、不同年龄同意与导入合法依据？ | 最小字段、校方核验、专业/隐私审批 | 任何真实资料导入前 |
| Q05 | 学年内一次测评的本地口径及必要复评例外？ | 保守场次计数，例外需依据与审批；不任意重复自测 | 任务发布前 |
| Q06 | 数据保留期、离校/转学与权利请求处理？ | 无永久留存；到期删除/受限留存策略必须明确 | M4 前 |
| Q07 | 团队、预算、交付日期、并发和设备？ | 阶段 Gate；使用文档标注的合成压测基线 | M0 / M1 |
| Q08 | 是否研究、区域上报、SSO 或医疗机构集成？ | MVP 不开放这些用途与接口 | 对应 M5 任务前 |
| Q09 | 原始报告可见性与监护沟通边界？ | 审核发布 + 依法查阅机制，不一刀切公开/禁止 | M2 报告设计前 |

未决事项影响的是相关实现/上线门槛，不阻止本次仓库与开发规划完成。
