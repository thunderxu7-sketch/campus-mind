# 名单导入可恢复性

## 管理员工作流

- 预检按文件行标注字段错误及原因；合法但已存在或批次内重复的 external ID 单独计为重复，不混入字段错误。
- 管理员可下载仅包含错误行的 CSV（含原始字段和错误原因）。CSV 在浏览器内由当前上传内容生成，服务器只保存批次和行号/状态/错误原因，不保存原始姓名、外部编号或整行上传数据；导出时会中和可触发表格公式执行的单元格。
- 提交按钮明确写为“仅导入有效行”。服务端按预检记录再次校验并只创建有效新行；提交结果分别显示新增、重复和跳过数量。
- 最近批次列表显示状态、计数和导入/回滚审计编号。

## 回滚边界

- 仅本次导入创建的学生可被回滚；既有重复行不受影响。
- 回滚采用可审计的停用，不物理删除学生或其身份哈希。只要该学生已有任何直接关联业务记录（例如凭证、监护关系、同意、测评任务、预约、权利申请等），就不自动停用，并将批次标记为“部分回滚”；没有后续关联的其他行仍可安全回滚。
- 回滚结果和每行状态原子提交、记录独立审计编号；重复请求不重复计数或重复审计。旧版本已提交批次缺少逐行新建学生引用时，服务端拒绝自动回滚，避免误停用。
- 回滚后保留去活的身份记录和批次审计证据；同一外部编号仍会被识别为历史重复，避免身份重建造成数据分叉。

## 持久化与隐私

- JSON/PostgreSQL state 都保留计数、批次审计引用及逐行创建学生引用；PostgreSQL 迁移 `004_import_recovery.sql` 增加受租户外键保护的字段和状态约束。
- 预检哈希仍绑定原始行，提交不能替换或重排上传内容。批次历史接口不返回 hash、原始 CSV、姓名或外部编号。
- 下载错误 CSV 是浏览器本地操作；离开页面、切换账号或关闭标签后，服务端没有可恢复的原始错误行文件。需要纠正数据时应保留本地原文件，并从错误 CSV 修复后重新预检。

## 验证范围

- 覆盖批内/已有数据重复、无有效行拒绝提交、混合行提交计数、提交审计编号、同租户批次历史、无关联/有下游引用的回滚及回滚幂等。
- 使用合成学生行，不使用真实学生名单；不部署服务。
